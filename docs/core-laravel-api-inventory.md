# Core (Laravel) API Inventory

> Comprehensive reference of all endpoints used by the Trydos application that are served by the **Core (Laravel)** backend (`process.env.BACKEND_URL`).
>
> Generated by an exhaustive scan of all `fetch`, `fetchData`, `HandleAuthedFetch`, `fetchServerData`, Next.js Route Handlers, and Server Actions across the codebase.

---

## 1. Routing Architecture & Classification

The frontend communicates with multiple backend services (`BACKEND_URL`, `GO_BACKEND_URL`, `STORIES_BACKEND_URL`, `NEXT_PUBLIC_CHAT_BACKEND_URL`, `COMMENT_BACKEND_URL`, `WALLET_BACKEND_URL`, `ELASTIC_BACKEND_URL`).

For the e-commerce storefront and seller portal, routing is resolved dynamically in `utils/server/tokenManager.ts` and `app/api/proxy/route.ts`:

1. **Exclusively Core (Laravel)**:
   - **Seller Dashboard**: All requests made on `server: "market-dashboard"` or hitting `/shop/*` and `/seller/*` paths resolve directly to Core (Laravel). The Go Gateway does not serve seller portal routes.
   - **Customer Operations**: Orders (`/customer/order/*`), Address book (`/customer/address/*`), Returns & Exchanges, Coupons (`/coupon/apply`), and legacy wallet records.
   - **Core Auth**: Phone OTP sending (`/auth/phone/send_otp`), verification (`/auth/phone/verify_otp_from_guest`, `/auth/phone/verify_otp`), and refresh token rotation (`/auth/refresh-token`).
   - **Platform Lookups**: Global countries configuration (`/countries`) and languages (`/languages`).

2. **Dual-Routed Storefront APIs**:
   - For public storefront endpoints on the Go allowlist (Cart, Wishlist, Starting Settings, Customer Profile, Product Details, FCM), **verified shoppers (authenticated with a valid phone number in `User-Data`) bypass the Go Gateway and are routed directly to Core (Laravel)**.
   - Guest visitors and unverified users are served by the **Go Gateway**.
