## Before any of these: the seed

`tests/e2e/harness/qaSeed.ts` is a Playwright **setup project**, and the `live`
project declares `dependencies: ["setup"]`, so it runs first, always. It is not a
case and has no row below.

It signs in as Shopper B, applies to be a seller, has the admin approve that,
creates the boutique, the location and the product, has the admin approve the
boutique, activates the product then the boutique, and waits for the search index.

Two paths: **~1.5 min** on an environment that already has the QA shop, and
**~15–20 min** the one time it builds a new one, most of which is the index
catching up. It runs only when `E2E_LANE=account`; unset means "do not seed", so
`playwright test` by hand never writes to a real environment.

**It never deletes**, and it **repairs** rather than skipping: a boutique an
earlier run left restricted in the shopping country is put right on the next run,
not left broken because it already looked finished.

## Notes for whoever runs this next

**`QA_VIEW_SECRET` must never be set on the deployed staging app.** It belongs
only in the environment the harness builds and starts. Unset, or under 32
characters, and the app treats QA mode as off — `QA-01` and `QA-02b` fail loudly
rather than silently passing.

**The seed skips, it does not fail, when a setting is missing**, and the skip
names which one. That matters: `live` depends on `setup`, so a *failing* setup
stops every live case in the lane (`32 did not run` on the run that proved it),
while a *skipped* one lets the rest of the suite through.

**The four BUY cases now buy the QA product** (`addFirstBuyableProduct` is
deleted). They have **not** been run since that change — that is the first job
of the next ticket, not a result claimed here.
