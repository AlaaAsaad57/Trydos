# Market / Market-Dashboard API Inventory

> Every backend API call that targets the e-commerce backend, split into two
> journeys:
> - **User Journey** — the shopper app (`market` channel + server-side
>   market-backend calls). **79 call sites.**
> - **Seller Journey** — the seller dashboard (`market-dashboard` channel, plus
>   the few seller `/shop/*` calls that ride the `market` channel). **43 call sites.**
>
> Generated by sweeping the whole codebase for `fetchData`, `HandleAuthedFetch`,
> `fetchServerData`, and proxy `fetch` call sites. Other backends (Stories,
> Wallet/RDB, Elastic, chat, comments) are out of scope here.
>
> Rows are numbered per journey. The `#` counts **call sites**, not distinct
> paths — a few endpoints (e.g. `qtyPriceDetails`, `startingSettings`) are called
> from more than one place and get one row each.

## Backend classification (Go vs Laravel)

`market` and `market-dashboard` are **logical channels, not hosts**. The real
host is chosen at request time by `isFromGoApi(url)` in
`utils/server/tokenManager.ts`:

| `isFromGoApi` | Base env var | Backend |
|---|---|---|
| true (`/checklist*`, Go product prefixes, or a `GO_APIS` suffix) | `NEXT_PUBLIC_GO_BACKEND_URL` | **Go** store gateway |
| false | `NEXT_PUBLIC_BACKEND_URL` | **Laravel** monolith |

Client calls route via `/api/proxy`; server calls (`serverRequests/*`) build the
full URL directly. Token: `MARKET-TOKEN` → falls back to `DEVICE-TOKEN` (guest);
on 401 a guest is auto-registered against Go `/auth/register-guest` and retried.
`market-dashboard` **never resolves to Go**.
